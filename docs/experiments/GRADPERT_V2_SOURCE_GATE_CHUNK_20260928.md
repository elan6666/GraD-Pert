# GraD-Pert v2 图来源门与 KDA 分块工程验证

## 范围与版本

本轮只改图编码器第 4 层稀疏 MLA 的边来源得分，并测试 KDA 分块大小；不启动正式 B0。训练路径仍为单向 KDA 写入、最终状态统一读取、各目标只在合法图邻域独立建状态，以及完整的预测、SSL1、SSL2。新来源门以零初始化，保留原有来源偏置、value、图边、前三层和 Teacher 的同构更新。方法公式与配置见 `docs/design/GRADPERT_V2_RELAY_METHOD_PLAN.md`。

先前已发布版本 `657b63ad509f5511b3cb4a585be0dc44a92aff65` 实现来源门和初始 m32 对照；容量回退配置发布于 `2043e09a4f4cb29317b9879da68e32e8d953ee1c`。后者的干净服务器源码在 `/data/yilangliu/GraD-Pert/development/source-v2-gate-chunks-2043e09`，发布收据 SHA256 为 `898df95cdfbcba7fb0e8ba54515ca317e4d08489d418a129c247d30d075b6734`。六份自包含 m16 配置均使用 Jurkat 当前单轮完整 loss，`λ₂=1`，DINO/iBOT/KoLeo 内部权重 `0.8/0.4/0.1`；双卡每卡微批 16、累积 2，即全局 batch 64。工程测速不能代替一轮训练或模型效果评估。

## 正确性与容量证据

最终服务器 Torch/CUDA 定向测试 `test_graph_source_key_gate.py`、`test_config.py`、`test_relay_method.py`：80 项通过。零来源门时图第 4 层输出及既有参数梯度与无门版本一致；非零门的多来源边得分和非法邻居遮罩经独立公式检验，门参数收到非零梯度。局部配置测试在 m16 扩展后为 44 项通过。上述测试只证明指定小形状和配置行为，不能证明随机训练长期效果。

m32×累积2×双卡（全局128）的独立单步预检：门控单独启用通过；图邻域扫描64加长序列扫描256的 `chunks_only` 在反向传播 CUDA OOM，门控与两种分块同时开启也 OOM。原始失败收据分别保留于服务器 `v2-gate-chunks-657b63a-chunks-only-m32-integration-r1`、`v2-gate-chunks-657b63a-combined-m32-integration-r1`；不得把进程退出视为成功。m16 的完整组合单步预检通过，并完成 checkpoint 重载，峰值已分配约 26.39 GB/卡，收据 `v2-gate-chunks-2043e09-combined-m16-integration-r1`。这不证明 128 步持续容量。

第一轮结果相对参考版：门控单独启用吞吐低 3.27%，只加两个扫描 chunk 低 4.58%，组合低 5.10%；行块 96 高 10.14%，行块 128 高 17.48%。行块 128 相对同方法、同扫描块的 row64 组合高 23.80%。图行块的收益来自减少独立图目标分批次数，但这不能抵消扫描256将峰值显存从参考版约 9.14 GB/卡提高到约 25–26 GB/卡的代价；全局 batch128 的 chunk 版本已在单步反向 OOM。`r1` 训练阶段 wall time 为 69.9–87.1 秒，启动至训练约 7.5–9.0 秒；数据等待比例约 6.2%–7.7%。

为核对运行顺序，另按 `combined_rows128 → reference` 的反向顺序重复相同 4 步。`r2` 行块 128 为 14.974 秒/更新、3.978 cells/s，参考为 17.878 秒/更新、3.376 cells/s；两组仍有 17.83% 的吞吐差。两次运行各自的批次顺序哈希相同，配置 SHA 与 `r1` 对应配置一致；日志无训练异常。收据分别为 `v2-gate-chunks-2043e09-combined_rows128-m16-bench-r2` 和 `v2-gate-chunks-2043e09-reference-m16-bench-r2`。这个重复支持短程速度差异稳定存在，却不证明一轮或更长时间的模型表现、最大持续 batch 或相同逐目标随机语义。

## 当前结论与下一步边界

来源门及指定的图扫描 64、序列扫描 256 均已实现并可通过 `combined_m16_a2` 自包含配置运行；行块 96、128 也有独立配置和双卡性能证据。**作为性能优化，不能把两个较大扫描块直接设为默认**：在 batch64 下组合吞吐比简单参考低 5.10%，峰值显存增加约 17.25 GB/卡，并使 batch128 在单步反向 OOM。行块 128 在短程吞吐上有重复收益，但先前严格语义审计指出行块改变可能重排随机数按目标的分配，且 BF16 结果不完全一致。本轮没有新增逐目标随机数修复、同输入完整状态对照或 128 步持续容量证据，所以不把 row128 宣称为等价优化，也不据此启动正式 B0。若后续决定采用该调度，应先将随机顺序与基因/目标 ID 绑定并验证输出、梯度、optimizer、EMA Teacher、center 与持续容量；不能仅以吞吐数据替代这些检查。

2026-09-27 用户要求旧 B0 立即停止。该运行 `nadig_jurkat-seed1-20260927T103751Z-9f821e38bded47d897da0461ee73d1b9` 的 `.exit=1`、epoch 0/5，目标进程退出；本轮不恢复它，也不启动新 B0。后续一轮配置中蒸馏②总系数为 1，DINO/iBOT/KoLeo 的内部系数为 0.8/0.4/0.1。旧运行的源码、配置和结果保持原样。

## 发布前局部探针（选候选，不是端到端结论）

来源为旧不可变服务器源码 `a6a2232b33d86469a8c67a061bd231b3bf7d46e6` 的 `chunk_delta_final_state`。双精度意义下相同块递推的不同分块会改变 FP32 求和顺序，因此需要有限精度和完整更新核验。BF16 K/V、FP32 decay/beta、4×64 头，GPU0；2 次预热、3 次同步的前向加输入梯度耗时中位数。此初探未生成持久收据，不单独用作采用证据。

## 验收次序

1. 本地配置、审计器和 CPU 小形状输出/梯度测试；服务器 BF16 图 L47、表达 L1000 的输出/梯度及 RNG 审计。
2. 双卡固定输入/随机状态的完整预测＋SSL1＋SSL2，含非零 LR 多步、优化器、EMA Teacher、center；行分块可能改变 PyTorch 随机数按目标的分配，须分别标注“同种分布”与“逐样本同 seed 完全对应”。
3. m32 ABBA 完整更新，分别对扫描 48/64、行 96/128 做同源码同数据同配置单因素对照。比较含数据等待的 cells/s、更新耗时及峰值显存，不从局部探针直接推断。
4. 仅对有竞争力且语义验收通过的候选做 m66 或更保守 batch 的持续容量复核。若吞吐、显存或稳定性不优于简单参考实现，保留参考分块 32/64；记录淘汰证据。

正式采用版本须单独发布并注明源码、配置和收据哈希。两步完整更新只是工程等价验证，不能当作长期模型效果结论。

## 首轮双卡等价失败后的隔离假设

已发布的全路径扫描候选 48/64 均把图 L47 与表达 L1000 的 KDA 同时改变。双卡真实输入的第一步完整更新未过原先的 `3e-5/3e-4` 容差：KoLeo 约有 0.002 的差异，部分图参数梯度最大绝对差约 0.00077，优化器状态也不同。收据位于服务器 `v2-chunk-4c82d9c-scan{48,64}-parity-20260927T2050Z*`；不得放宽阈值宣称通过。

新增独立假设：**仅增大 Cell/Response self 和 cross 的长序列扫描块，图邻域仍为 32**，用 `relay_sequence_chunk_size` 显式覆盖。旧 `relay_scan_chunk_size` 保持原全路径语义，已发生的探针仍可复现。单独的 `sequence48/64_m32_a2` 配置只变这一字段。它需要新发布版本、图路径未变核验、完整非零学习率更新和端到端吞吐；成功前不进入默认配置。

图行块的合成 BF16 审计使用 192 目标×47 邻居、宽度 256、相同权重与输入、dropout 0 的 eval 输出；脚本 SHA256 `540125dcfcb75b9ed74cc313d49591cad470a75d4dcefb342bed1ceac3449f25`，服务器收据 `/data/yilangliu/GraD-Pert/development/v2-chunk-row-semantics-4c82d9c.json`。相对于 64 行，96/128 行的输出最大绝对差分别是 0.001953/0.004395，未过 `3e-5/3e-4`；所测输入与 key/value 梯度过该容差。改行块后即使固定种子，逐目标随机顺序分数约三分之二不同，dropout 掩码也不逐目标对应。这不等于边际随机分布改变，但**不能声称与原训练同 seed 数值轨迹等价**。端到端计时只判断是否值得继续研究稳定随机分配和数值核；在其完成前不采用行块候选。

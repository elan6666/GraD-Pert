# GraD-Pert v2 来源门：最大可持续 batch 与 chunk 搭配

## 问题与约束

目标是在双 RTX 5090、完整预测＋SSL1＋SSL2、固定每卡累积 2 次、1000 表达查询基因和既定随机视图下，寻找**最大经过持续验证的物理微批**，并在可用容量内比较训练吞吐。全局 batch 为 `每卡微批 × 2 累积 × 2 卡`；单纯提高累积次数不计作 GPU 容量提高。所有候选启用图第 4 层来源逐维 key 门，保留单向 KDA 写入与最终状态读取、合法图邻域、λ₂=1、跨双卡 KoLeo 和原数据划分。不启动正式 B0。

先前旧图版本在每卡 66、全局 264 的 128 步容量测试通过；每卡 68、全局 272 在第 22 步 OOM。新来源门版本 `d2410efdc81a9690644ef2d165c2dea374ba0fbb` 的每卡 66 单步更新和 checkpoint 重载通过，峰值预留约 31.43 GB/卡。旧版本的容量边界不能直接转移到新版本。

## 候选和验收顺序

以新来源门的默认 `scan32 / sequence32 / graph_rows64` 为锚。自包含配置在 `configs/v2/source_key_gate_capacity_jurkat/`，仅改变微批、图目标行块或序列扫描块：

| 每卡微批 | 全局 batch | 图扫描 | 序列扫描 | 图目标行块 | 用途 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 66 | 264 | 32 | 32 | 64 | 当前单步通过的锚点 |
| 67/68/70 | 268/272/280 | 32 | 32 | 64 | 查容量边界 |
| 68/70 | 272/280 | 32 | 32 | 32 | 减小并行图目标块的显存压力 |
| 68/70 | 272/280 | 32 | 16 | 64 | 减小长序列分块临时量 |
| 66 | 264 | 32 | 32 | 96/128 | 查已观察到的图目标并行提速能否在大 batch 成立 |

单步筛选开始后观察到：微批70时序列块由32改16，使峰值预留从约32.35 GB/卡降至28.90 GB/卡；图行64改32的峰值不变。因此追加序列16的微批72/74/76/77/78/80，以及序列32的微批72作为边界对照。追加不是宣称这些配置稳定或更快；只在新发布提交上用独立ID筛选。

最终选择须同时报告：通过的最高持续微批、失败上界、双卡含数据等待 cells/s、峰值已分配/预留显存、启动和稳态时间、来源/配置哈希，以及是否保留原 chunk 默认。如果更大物理 batch 降低总吞吐或显存余量不足，会把“容量最大”和“实用训练配置”分开报告。

## Mechanism and decision

Prepare Teacher/optimizer/checkpoint state on CPU and move only the Student to
GPU, as in the existing independent evaluator. Cap only its allocator, retaining
original batch128 and1000-query recipe. GPU0 has measured headroom beside the
~19GiB-per-rank training footprint. A separate process has independent RNG state;
there is no alteration to gene identity, views, controls, losses or update timing.

This demonstrates bounded shared-device feasibility, not full-run speedup. The
20.3% slowdown is an interval comparison crossing an epoch save boundary, with
finite sample and changing view shapes. A rough makespan forecast using the
prior same-shape8.25s standalone inference probe suggests potential overlap gain,
but it is a different condition/checkpoint and is NOT a matched standalone U4
benchmark. Full-run throughput/stability remain to be measured.

Proceed with one capped U4 evaluator on GPU0 while the exact existing U3 fit
continues; do not add a second shared evaluator without evidence. The new adopted
schedule never starts another fit. Retire only the exact old controller parent;
its existing child retains its GPU leases and is adopted by exact cmdline hash.
Then evaluate U3 on idle exclusive GPUs0,1. Evaluation code identity is separately
recorded; old immutable launch/config/checkpoint identities remain unchanged.

If overlap fails or makespan evidence becomes unfavourable, preserve evidence and
hand back for the requested fallback: stop U3 from a sealed full-state checkpoint,
finish U4 evaluation, then exact same-source full-state resume (not new-stage LR).
Preserve all interrupted attempts and replay the incomplete epoch explicitly.

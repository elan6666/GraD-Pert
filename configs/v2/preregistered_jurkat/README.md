# Jurkat v2 preregistered matrix

Reference: synchronous world2, accumulation1, physical64/rank, global128,
evaluation cell batch128. H3 compares global64/128/148 from passed full-chain
receipts; no unmeasured accumulated batch is included.

All47 training rows across15groups are self-contained YAML files. The parent,
manifest and per-row hashes were verified against the declared factor changes.
B0/H1 need exact launch-source/config/seed preflight. Later groups are explicitly
prospective; run_group rejects them until prepare_followup regenerates a new
group from actual validation-only H1/H2/H3 selection receipts. Do not change the
prospective status by hand. These are nominal configurations, not ready jobs.

Order: B0 reference, H1 learning rate, H2 weight decay, H3 measured batch, P1
width, then L0/L1/L2 losses, A1/A2/A3/A4 structure/initialization, S1/S2 reduction/
sampling, and G1 heldout-expression training. Context scaling and D1 response
diagnostics reuse frozen checkpoints with separate sealed evaluation protocols.

Generator execution used publishedffd94b9. Server originals are under
`/data/yilangliu/GraD-Pert/development/v2-preregistered-jurkat-ffd94b9`; copied
YAML/JSON bytes are unchanged. Absolute capacity/holdout paths refer to sealed
server evidence and must stay accessible during server verification. Canonical
splits,300-control manifests and data axes are inherited from the existing v1
contracts. Other datasets use prepare_dataset/prepare_matrix with their own
capacity and holdout evidence; do not transplant Jurkat paths.
